## Giải thích đầy đủ các field trong response `4001`

Response `4001` là kết quả backend trả về sau một lượt spin thành công.

Mục tiêu của response mới là:

```txt
Frontend không cần đọc reels math.
Frontend không cần tự đoán item nào rơi.
Frontend chỉ cần đọc animationReels và cascadeSteps[].animation* để diễn animation.
```

---

# 1. Field cấp ngoài response

## `cmd`

```json
"cmd": 4001
```

Mã command response.

`4001` nghĩa là backend trả kết quả của lệnh PLAY/SPIN.

Frontend dùng field này để phân loại message socket.

---

## `spinId`

```json
"spinId": "SPIN_001"
```

ID duy nhất của lượt spin.

Dùng cho:

```txt
- tracking log
- debug
- history
- đối chiếu với backend
```

Frontend thường không cần dùng field này để render animation.

---

## `roundId`

```json
"roundId": "RND_001"
```

ID round xử lý tiền.

Một round thường gắn với:

```txt
- bet transaction
- settle transaction
- payout status
- history
- reconciliation
```

Frontend có thể lưu để debug hoặc gửi cho support khi cần kiểm tra giao dịch.

---

## `roomId`

```json
"roomId": 1
```

Room mà người chơi đang chơi.

Dùng để xác định mức cược, cấu hình room, bet option tương ứng.

---

# 2. `animationMeta`

```json
"animationMeta": {
  "displayLayout": [6, 5, 5, 5, 6],
  "rowOrder": "ARRAY_ORDER",
  "dropRule": "REMOVE_THEN_KEEP_ORDER_THEN_APPEND_NEW",
  "description": "..."
}
```

`animationMeta` mô tả quy tắc layout và quy tắc drop cho frontend.

---

## `animationMeta.displayLayout`

```json
"displayLayout": [6, 5, 5, 5, 6]
```

Layout frontend dùng để render visual board.

Ý nghĩa:

```txt
Cột 0 có 6 item
Cột 1 có 5 item
Cột 2 có 5 item
Cột 3 có 5 item
Cột 4 có 6 item
```

Đây là visual layout, không phải math layout.

Frontend render theo 5 cột từ trái sang phải:

```txt
animationReels[0] = cột 1
animationReels[1] = cột 2
animationReels[2] = cột 3
animationReels[3] = cột 4
animationReels[4] = cột 5
```

---

## `animationMeta.rowOrder`

```json
"rowOrder": "ARRAY_ORDER"
```

Cho biết thứ tự row trong mỗi cột sẽ đi đúng theo thứ tự mảng backend trả về.

Ví dụ:

```json
[
  { "symbol": "ITEM_5" },
  { "symbol": "ITEM_5" },
  { "symbol": "ITEM_2" },
  { "symbol": "ITEM_5" },
  { "symbol": "ITEM_7" },
  { "symbol": "ITEM_7" }
]
```

Frontend đọc đúng theo thứ tự:

```txt
row 0 = ITEM_5
row 1 = ITEM_5
row 2 = ITEM_2
row 3 = ITEM_5
row 4 = ITEM_7
row 5 = ITEM_7
```

Không tự đảo mảng.

---

## `animationMeta.dropRule`

```json
"dropRule": "REMOVE_THEN_KEEP_ORDER_THEN_APPEND_NEW"
```

Quy tắc drop chính.

Nghĩa là:

```txt
1. Remove item thắng.
2. Giữ nguyên thứ tự các item còn lại.
3. Item phía sau vị trí bị remove dồn lên để lấp chỗ trống.
4. Item mới append vào cuối cột.
```

Ví dụ:

```txt
Before:
5,5,2,5,7,7

Remove ITEM_7 row 4:
5,5,2,5,_,7

Dồn item phía sau lên:
5,5,2,5,7,_

Append item mới vào cuối:
5,5,2,5,7,1
```

---

## `animationMeta.description`

```json
"description": "Trong mỗi cột, backend giữ nguyên thứ tự mảng..."
```

Mô tả bằng ngôn ngữ tự nhiên cho FE/dev hiểu rule drop.

Field này không bắt buộc dùng trong code render. Nó chủ yếu để debug/documentation.

---

# 3. `animationReels`

```json
"animationReels": [...]
```

Board visual ban đầu sau khi spin dừng.

Frontend dùng `animationReels` để render board đầu tiên trước khi chạy cascade.

Nếu spin không thắng:

```txt
Frontend chỉ render animationReels và kết thúc.
```

Nếu spin có thắng:

```txt
Frontend render animationReels,
sau đó chạy từng cascadeSteps[].
```

---

## Cấu trúc `animationReels`

`animationReels` là mảng 5 cột:

```txt
animationReels[0] = cột 0
animationReels[1] = cột 1
animationReels[2] = cột 2
animationReels[3] = cột 3
animationReels[4] = cột 4
```

Mỗi cột là một mảng cell.

Ví dụ một cell:

```json
{
  "cellId": "s1-c0-r4",
  "symbol": "ITEM_7",
  "golden": false,
  "displayOnly": false
}
```

---

# 4. Field của từng item/cell

## `cellId`

```json
"cellId": "s1-c0-r4"
```

ID dùng để tracking cùng một item trong quá trình animation.

Quan trọng:

```txt
cellId là identity của item.
cellId không phải vị trí hiện tại.
```

Ví dụ:

```json
{
  "cellId": "s1-c0-r5",
  "symbol": "ITEM_7",
  "fromRow": 5,
  "toRow": 4
}
```

Nghĩa là item có identity `s1-c0-r5` ban đầu ở row 5, sau đó move lên row 4.

Dù item đổi vị trí, `cellId` vẫn giữ nguyên để frontend biết đó là cùng một item.

Frontend không được suy luận row hiện tại từ tên `cellId`. Vị trí hiện tại phải lấy từ:

```txt
row
fromRow
toRow
```

tùy field đang đọc.

---

## `symbol`

```json
"symbol": "ITEM_7"
```

Mã symbol/item để frontend map asset.

Ví dụ:

```txt
WILD
SCATTER
ITEM_1
ITEM_2
ITEM_3
ITEM_4
ITEM_5
ITEM_6
ITEM_7
```

Nếu backend trả:

```json
"symbol": "WILD"
```

thì FE render icon Wild.

---

## `golden`

```json
"golden": true
```

Cho biết item đó có phải golden item hay không.

Ý nghĩa:

```txt
golden = true  => render item dạng golden
golden = false => render item thường
```

Lưu ý:

```txt
Golden là trạng thái của item.
Golden không phải do drop gom thành.
```

Nếu golden item tham gia win, nó sẽ không bị remove mà transform thành `WILD` thông qua `visualGoldenTransforms`.

---

## `displayOnly`

```json
"displayOnly": true
```

Cho biết cell này có phải ô visual-only hay không.

Ý nghĩa:

```txt
displayOnly = true  => item chỉ dùng để hiển thị/animation buffer
displayOnly = false => item nằm trong vùng chính frontend render như item playable
```

Trong visual layout `[6,5,5,5,6]`, cột 0 và cột 4 có thêm item buffer.

Quan trọng:

```txt
displayOnly phụ thuộc vào vị trí hiện tại, không phải thuộc tính cố định của item.
```

Một item có thể ban đầu là:

```json
{
  "cellId": "s1-c0-r5",
  "symbol": "ITEM_7",
  "displayOnly": true
}
```

Nhưng khi item đó move vào vùng chính:

```json
{
  "cellId": "s1-c0-r5",
  "symbol": "ITEM_7",
  "fromDisplayOnly": true,
  "toDisplayOnly": false
}
```

Tức là item từ buffer row đã move vào vùng chính và trở thành item render bình thường.

---

# 5. `cascadeSteps`

```json
"cascadeSteps": [...]
```

Danh sách các cascade step trong một lượt spin.

Nếu spin thua:

```json
"cascadeSteps": []
```

Nếu spin thắng và có cascade:

```txt
cascadeSteps[0] = step 1
cascadeSteps[1] = step 2
cascadeSteps[2] = step 3
...
```

Frontend chạy từng step theo thứ tự.

---

# 6. Field trong từng `cascadeSteps[]`

## `step`

```json
"step": 1
```

Số thứ tự cascade step.

Response thật phải bắt đầu từ:

```txt
step = 1
```

Không nên bắt đầu từ step 3 hoặc step 4 trong response production, vì FE có thể hiểu nhầm là thiếu step trước đó.

---

## `mode`

```json
"mode": "BASE"
```

Mode game tại step hiện tại.

Ví dụ:

```txt
BASE = game thường
FREE_SPIN = đang trong free spin
```

FE có thể dùng để render UI hoặc multiplier khác nhau.

---

## `multiplier`

```json
"multiplier": 3
```

Hệ số nhân áp dụng cho step đó.

Ví dụ trong BASE:

```txt
step 1 có thể x1
step 2 có thể x2
step 3 có thể x3
step 4+ có thể x5
```

Frontend dùng để hiển thị multiplier nếu UI cần.

---

## `stepWin`

```json
"stepWin": 675
```

Tổng tiền thắng của riêng cascade step này.

Nếu trong một step có nhiều win, `stepWin` là tổng tiền thắng của tất cả win trong step đó.

---

## `animationReelsBeforeDrop`

```json
"animationReelsBeforeDrop": [...]
```

Board visual trước khi remove item thắng ở step hiện tại.

Frontend dùng field này để:

```txt
1. Render board đầu step.
2. Highlight item thắng.
3. Chuẩn bị remove/drop.
```

Rule quan trọng:

```txt
Nếu có step tiếp theo:
cascadeSteps[n].animationReelsAfterDrop
phải bằng
cascadeSteps[n+1].animationReelsBeforeDrop
```

Điều này giúp animation không bị nhảy board giữa các cascade step.

Symbol thắng.

Frontend có thể dùng để hiện text hoặc hiệu ứng win theo loại item.

---

## `visualWins[].matchedReels`

```json
"matchedReels": 3
```

Số cột liên tiếp tạo thành win.

Ví dụ:

```txt
matchedReels = 3 nghĩa là thắng qua 3 cột.
matchedReels = 5 nghĩa là thắng qua 5 cột.
```

---

## `visualWins[].ways`

```json
"ways": 1
```

Số ways thắng của symbol đó trong step hiện tại.

FE có thể dùng để hiển thị thông tin chi tiết nếu cần.

---

## `visualWins[].winAmount`

```json
"winAmount": 675
```

Số tiền thắng của win đó.


Các vị trí visual của item thắng để FE highlight.

Ý nghĩa:

```txt
col = index cột

```

Frontend dùng field này để làm sáng item thắng trước khi remove/transform.

# 8. `animationColumns`

```json
"animationColumns": [...]
```

Đây là field quan trọng nhất để frontend diễn drop theo từng cột.

Mỗi phần tử trong `animationColumns` mô tả animation của một cột.

Cấu trúc mỗi cột:

```json
{
  "col": 0,
  "before": [],
  "removed": [],
  "moves": [],
  "newSymbols": [],
  "after": []
}
```

Frontend không cần tự so sánh before/after để đoán item nào rơi. Backend đã nói rõ:

```txt
- trước đó cột có gì
- remove item nào
- item nào move từ row nào sang row nào
- item mới nào xuất hiện
- sau cùng cột còn gì
```

---

## `animationColumns[].col`

```json
"col": 0
```

Index cột.

```txt
0 = cột 1 ngoài cùng bên trái
1 = cột 2
2 = cột 3
3 = cột 4
4 = cột 5 ngoài cùng bên phải
```

---

## `animationColumns[].before`

```json
"before": [
  {
    "row": 0,
    "cellId": "s1-c0-r0",
    "symbol": "ITEM_5",
    "golden": false,
    "displayOnly": true
  }
]
```

Trạng thái cột trước khi remove/drop.

Mỗi item trong `before` có đầy đủ:

```txt
row
cellId
symbol
golden
displayOnly
```

Frontend có thể dùng `before` để debug hoặc render riêng từng cột.

---

## `animationColumns[].removed`

```json
"removed": [
  {
    "row": 4,
    "cellId": "s1-c0-r4",
    "symbol": "ITEM_7",
    "golden": false,
    "displayOnly": false
  }
]
```

Danh sách item bị remove/nổ trong cột đó.

Frontend dùng để chạy hiệu ứng:

```txt
explode
fade out
remove
```

Lưu ý:

```txt
Golden item thắng không nằm trong removed.
Golden item thắng sẽ nằm trong visualGoldenTransforms.
```

---

## `animationColumns[].moves`

```json
"moves": [
  {
    "cellId": "s1-c0-r5",
    "symbol": "ITEM_7",
    "golden": false,
    "fromRow": 5,
    "toRow": 4,
    "fromDisplayOnly": true,
    "toDisplayOnly": false
  }
]
```

Danh sách item cũ còn lại và có di chuyển sau khi remove.

Ý nghĩa:

```txt
cellId = identity của item đang move
symbol = symbol của item
golden = item có golden không
fromRow = row ban đầu
toRow = row sau khi dồn/drop
fromDisplayOnly = trạng thái displayOnly trước khi move
toDisplayOnly = trạng thái displayOnly sau khi move
```

Ví dụ:

```txt
ITEM_7 từ row 5 move lên row 4.
Ban đầu displayOnly=true vì ở buffer row.
Sau khi vào row 4 thì displayOnly=false vì đã vào vùng chính.
```

---

## `animationColumns[].newSymbols`

```json
"newSymbols": [
  {
    "cellId": "s1-new-c0-r5",
    "symbol": "ITEM_1",
    "golden": false,
    "toRow": 5,
    "displayOnly": true,
    "enterFromRow": 6
  }
]
```

Danh sách item mới được thêm vào cột sau khi remove/drop.

Ý nghĩa:

```txt
cellId = identity mới của item mới
symbol = symbol mới
golden = item mới có golden không
toRow = row cuối cùng item mới sẽ nằm
displayOnly = trạng thái displayOnly tại vị trí mới
enterFromRow = item mới đi vào từ row nào
```

Theo rule hiện tại:

```txt
Item mới append vào cuối cột.
```

Ví dụ:

```txt
Before:
5,5,2,5,7,7

Remove:
5,5,2,5,_,7

Move:
5,5,2,5,7,_

New:
5,5,2,5,7,1
```

`ITEM_1` là new symbol ở row cuối.

---

## `animationColumns[].after`

```json
"after": [
  {
    "row": 4,
    "cellId": "s1-c0-r5",
    "symbol": "ITEM_7",
    "golden": false,
    "displayOnly": false
  }
]
```

Trạng thái cuối cùng của cột sau khi:

```txt
1. remove item thắng
2. move item còn lại
3. append item mới
4. apply golden transform nếu có
```

Rule bắt buộc:

```txt
animationColumns[].after
phải khớp với cột tương ứng trong
animationReelsAfterDrop
```

Ví dụ:

```txt
animationColumns[0].after
phải bằng
animationReelsAfterDrop[0]
```

# 9. `visualGoldenTransforms`

```json
"visualGoldenTransforms": [
  {
    "cellId": "s1-c2-r2",
    "fromSymbol": "ITEM_5",
    "toSymbol": "WILD",
    "fromGolden": true,
    "toGolden": false,
    "from": { "col": 2, "row": 1 },
```

Danh sách golden item thắng và transform thành `WILD`.

Field này dùng để FE diễn hiệu ứng:

```txt
Golden ITEM_5 -> WILD
```

---

## `visualGoldenTransforms[].cellId`

```json
"cellId": "s1-c2-r2"
```

Identity của item golden cần transform.

---

## `visualGoldenTransforms[].fromSymbol`

```json
"fromSymbol": "ITEM_5"
```

Symbol ban đầu trước khi transform.

---

## `visualGoldenTransforms[].toSymbol`

```json
"toSymbol": "WILD"
```

Symbol sau khi transform.

Hiện rule là:

```txt
Golden item thắng transform thành WILD.
```

---

## `visualGoldenTransforms[].fromGolden`

```json
"fromGolden": true
```

Cho biết item trước khi transform là golden.

---

## `visualGoldenTransforms[].toGolden`

```json
"toGolden": false
```

Cho biết item sau khi transform không còn là golden.

---

## `visualGoldenTransforms[].from`

```json
"from": { "col": 2, "row": 1 }
```

Vị trí visual trước khi transform.

---

## `visualGoldenTransforms[].to`

```json
"to": { "col": 2, "row": 1 }
```

Vị trí visual sau khi transform.

Thường `from` và `to` giống nhau, vì golden transform là transform tại chỗ, không phải move/drop.

---

## Rule quan trọng của golden

```txt
Golden không phải do item drop gom thành.
Golden là trạng thái có sẵn của item.
Nếu golden item tham gia win, nó không bị remove.
Nó transform thành WILD qua visualGoldenTransforms.
```

# 10. `animationReelsAfterDrop`

```json
"animationReelsAfterDrop": [...]
```

Board visual cuối cùng sau khi xử lý xong cascade step.

Nó là kết quả cuối của:

```txt
animationReelsBeforeDrop
+ removed
+ moves
+ newSymbols
+ visualGoldenTransforms
```

Frontend dùng `animationReelsAfterDrop` để snap board về trạng thái cuối sau animation.

Rule bắt buộc:

```txt
animationReelsAfterDrop phải khớp animationColumns.after.
```

Nếu còn cascade step tiếp theo:

```txt
cascadeSteps[n].animationReelsAfterDrop
=
cascadeSteps[n+1].animationReelsBeforeDrop
```

# 12. `balance`

```json
"balance": 1002475
```

Số dư mới của người chơi sau khi backend xử lý tiền thành công.

Frontend chỉ nên update balance khi:


# 14. `seamless`

```json
"seamless": {
  "enabled": true,
  "payoutStatus": "SUCCESS"
}
```

Trạng thái xử lý ví Seamless.

---

## `seamless.enabled`

```json
"enabled": true
```

Cho biết game có đang dùng Seamless Wallet không.

---

## `seamless.payoutStatus`

```json
"payoutStatus": "SUCCESS"
```

Trạng thái xử lý tiền.

Các trạng thái FE cần hiểu:

```txt
SUCCESS
=> tiền đã xử lý xong
=> FE được update balance

BET_PENDING / SETTLE_PENDING / JACKPOT_PENDING / CREATED
=> giao dịch chưa xong
=> FE không update balance như success
=> nên lock spin hoặc hiển thị đang xử lý

FAILED / FAILED_NEED_REVIEW / INSUFFICIENT_BALANCE
=> giao dịch lỗi hoặc cần review
```

# 21. Flow frontend render chuẩn

Frontend render theo thứ tự:

```txt
1. Nhận response cmd = 4001.
2. Render animationReels ban đầu.
3. Nếu cascadeSteps rỗng:
   - không có cascade
   - hiển thị kết quả cuối
4. Nếu có cascadeSteps:
   - chạy từng step theo thứ tự.
5. Với mỗi step:
   5.1 Render animationReelsBeforeDrop.
   5.2 Highlight visualWins.positions.
   5.3 Remove animationColumns[].removed.
   5.4 Move item cũ theo animationColumns[].moves.
   5.5 Add item mới theo animationColumns[].newSymbols.
   5.6 Nếu có visualGoldenTransforms thì chạy golden -> WILD.
   5.7 Snap board về animationReelsAfterDrop.
6. Sau step cuối:
   - hiển thị totalWin
   - update balance nếu seamless.payoutStatus = SUCCESS.
```

# 22. Ví dụ flow một cột

Với cột:

```txt
Before:
5,5,2,5,7,7
```

Win là `ITEM_7` ở row 4.

## Step remove

```txt
5,5,2,5,_,7
```

## Step move

Item `ITEM_7` row 5 move lên row 4:

```txt
5,5,2,5,7,_
```

## Step new symbol

Item mới `ITEM_1` append vào row 5:

```txt
5,5,2,5,7,1
```

## After

```txt
5,5,2,5,7,1
```

Đây chính là rule:

```txt
REMOVE_THEN_KEEP_ORDER_THEN_APPEND_NEW
```

# 23. Tóm tắt ngắn cho frontend

```txt
Frontend không cần đọc reels math.
Frontend không cần tự so sánh before/after để đoán item rơi.

Backend đã trả:
- board trước drop
- item thắng để highlight
- item bị remove theo từng cột
- item cũ move từ row nào sang row nào
- item mới append vào row nào
- golden item nào transform thành WILD
- board cuối sau drop

Frontend chỉ việc render đúng theo animationColumns và snap về animationReelsAfterDrop.
```
